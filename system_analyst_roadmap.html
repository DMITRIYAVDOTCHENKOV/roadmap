📌 I. Общие вопросы о работе аналитика
1. Кто такой аналитик?▼

Аналитик — специалист, который занимается сбором, обработкой и анализом данных с целью получения полезной информации. Использует различные методы и инструменты (статистический анализ, SQL, моделирование) для изучения данных, делает выводы и рекомендации, которые помогают компаниям принимать обоснованные решения.

📚 Яндекс Практикум: Кто такой системный аналитик 📚 Stepik: Курсы по аналитике 📝 Habr: Виды аналитиков
2. Какие виды аналитиков бывают?▼

• Бизнес-аналитик — оптимизация бизнес-процессов
• Системный аналитик — анализ ИТ-систем и интеграций
• Data Analyst — анализ данных, статистика
• Финансовый аналитик — финансовое планирование
• Маркетинговый аналитик — анализ рынка и кампаний
• Продуктовый аналитик — метрики продукта
• BI-аналитик — визуализация и отчетность

📝 Habr: Виды аналитиков в IT 📚 Stepik 🎓 Яндекс Практикум
3. В чём разница между системным и бизнес-аналитиком?▼

Бизнес-аналитик: отвечает на вопрос «ЧТО нужно бизнесу?» (цели, процессы, метрики, стратегии). Фокус на бизнес-задачах.

🗄️ IX. Базы данных и SQL
29. Что такое реляционная БД?▼

БД, где данные хранятся в таблицах (отношениях), связанных ключами. Основные принципы: атомарность ячеек, уникальные имена столбцов, первичные ключи, внешние ключи для связей, нормализация для устранения избыточности.

30. Что такое нормализация?▼

Процесс организации данных для устранения избыточности и аномалий.
• 1NF: атомарные значения
• 2NF: нет частичной зависимости от составного ключа
• 3NF: нет транзитивной зависимости неключевых атрибутов

На практике: нормализуют до 3NF для OLTP, денормализуют для аналитики (OLAP).

• 1:M (Один-ко-многим): отдел → сотрудники
• M:N (Многие-ко-многим): студенты ↔ курсы (через промежуточную таблицу enrollment)

33. Чем LEFT JOIN отличается от INNER JOIN?▼

INNER JOIN: только строки, где есть совпадение в обеих таблицах.

LEFT JOIN: все строки из левой таблицы + совпадения из правой (если нет — NULL в полях правой).

Пример: показать всех клиентов + их заказы (даже если заказов нет) → LEFT JOIN.

34. Зачем нужны индексы?▼

Индексы ускоряют поиск, сортировку и соединение таблиц за счёт дополнительной структуры данных (B-tree, hash и др.).

Минусы: замедляют INSERT/UPDATE/DELETE, занимают место.

Совет: индексируйте поля в WHERE, JOIN, ORDER BY; избегайте избыточных индексов.

35. Что такое первичный и внешний ключ?▼

Primary Key: уникальный идентификатор записи (NOT NULL, UNIQUE). Одна таблица — один PK.

Foreign Key: ссылка на PK другой таблицы, обеспечивает ссылочную целостность (CASCADE, SET NULL и др.).

📚 Stepik: Ключи в БД 📝 Habr 🎓 Яндекс Практикум
36. Что такое транзакция? ACID?▼

Транзакция: последовательность операций, выполняемых как единое целое.

ACID:
• Atomicity — атомарность (всё или ничего)
• Consistency — согласованность (данные в валидном состоянии)
• Isolation — изолированность (параллельные транзакции не мешают)
• Durability — долговечность (после COMMIT изменения не потеряются)

📝 Habr: Транзакции и ACID 📚 Stepik 🇷🇺 PostgreSQL docs
37. Чем TRUNCATE отличается от DELETE?▼

DELETE: удаляет строки по условию, можно откатить (ROLLBACK), срабатывают триггеры, медленнее.

TRUNCATE: удаляет ВСЕ строки, нельзя откатить в некоторых СУБД, не срабатывают триггеры, быстрее (сбрасывает таблицу).

🏗️ X. Архитектура
38. Монолит vs Микросервисы?▼

Монолит: одно приложение, проще в разработке/тестировании, но сложно масштабировать и обновлять.

Микросервисы: независимые сервисы, гибкое масштабирование, отказоустойчивость, но сложнее в управлении, мониторинге, отладке.

Выбор: начинайте с модульного монолита, переходите на микросервисы при росте сложности.

• Presentation: UI (веб/мобильное приложение)
• Business Logic: обработка правил, расчёты, API
• Data: БД, кэш, файловое хранилище

Толстый клиент: логика на стороне клиента (десктоп/мобильное приложение), работает оффлайн, но сложнее обновлять.

Тонкий клиент: логика на сервере (веб-браузер), легко обновлять, но требует постоянного соединения.

42. REST vs SOAP: в чём разница?▼

REST: архитектурный стиль, HTTP-методы, JSON/XML, stateless, кэшируемый, проще.

SOAP: протокол, XML, WSDL, встроенная безопасность (WS-Security), строгий контракт.

Выбор: REST — для веб/мобильных API; SOAP — для корпоративных/госсистем с высокими требованиями к безопасности.

49. Синхронное vs Асинхронное взаимодействие?▼

Синхронное: клиент ждёт ответа (HTTP-запрос). Просто, но блокирует, неустойчиво к сбоям.

Асинхронное: клиент отправил → забыл, ответ через callback/очередь (Kafka, webhook). Сложнее, но масштабируемее, отказоустойчивее.

50. Что такое CAP-теорема?▼

В распределённой системе нельзя одновременно обеспечить:
• Consistency (согласованность: все узлы видят одни данные)
• Availability (доступность: каждый запрос получает ответ)
• Partition tolerance (устойчивость к разделению сети)

Выбор: при сетевом сбое (P) приходится выбирать между C и A.

🔐 XIV. Безопасность
56. Авторизация vs Аутентификация?▼

Аутентификация: проверка «кто ты?» (логин/пароль, 2FA, биометрия).

Авторизация: проверка «что тебе можно?» (роли, права доступа, scopes).

Пример: OAuth 2.0: аутентификация → получение токена → авторизация через scopes.

57. Как работает HTTPS?▼

HTTP + шифрование TLS/SSL:
1. Клиент и сервер согласуют версию TLS и шифры
2. Сервер отправляет сертификат (проверка ЦС)
3. Генерация сессионного ключа (асимметричное → симметричное шифрование)
4. Обмен данными в зашифрованном виде

Зачем: защита от MITM, конфиденциальность, целостность.

58. Что такое хеширование?▼

Преобразование данных в фиксированную строку (хеш) с помощью односторонней функции.

Свойства: детерминированность, лавинный эффект, невозможность восстановления.

Применение: хранение паролей (bcrypt, argon2), проверка целостности (SHA-256), цифровые подписи.

59. Что такое OAuth 2.0?▼

Протокол делегированного доступа: приложение получает ограниченный доступ к ресурсам пользователя без пароля.

Роли: Resource Owner (пользователь), Client (приложение), Authorization Server, Resource Server.

Flows: Authorization Code (веб), PKCE (мобильные), Client Credentials (сервис-сервис).

60. Что такое JWT?▼

JWT (JSON Web Token) — компактный способ передачи claims между сторонами.

Структура: Header.Payload.Signature (base64url).

Зачем: stateless-аутентификация в микросервисах, передача прав (scopes).

🔷 XV. Продвинутые темы архитектуры
61. Что такое DDD (Domain-Driven Design)?▼

103. Чем отличается UNION от UNION ALL?▼

UNION: объединяет результаты запросов, удаляя дубликаты. Требует дополнительной сортировки для удаления повторов → медленнее.

UNION ALL: объединяет результаты без удаления дубликатов. Быстрее, так как не требует дополнительной обработки.

Пример: если нужно получить список всех заказов из двух таблиц и дубликаты не важны → UNION ALL. Если нужны только уникальные записи → UNION.

104. Что такое поисковые пути в базах данных?▼

Поисковые пути (search paths) — механизм в PostgreSQL для определения порядка поиска объектов (таблиц, функций, типов) по схемам.

Зачем: позволяет использовать объекты из разных схем без указания схемы в запросе.

Пример:
SET search_path TO schema1, schema2, public;
Теперь при запросе SELECT * FROM users система будет искать таблицу users сначала в schema1, затем в schema2, затем в public.

105. Как проверить, что сообщение брокера получено в полном объеме?▼

106. Чем корпоративная шина отличается от ETL-инструмента?▼

107. Чем брокер сообщений отличается от корпоративной шины?▼

• Надстройка над брокерами + дополнительные функции

• Единая точка управления интеграциями

Аналогия: брокер — почтовое отделение; ESB — логистический центр с сортировкой и маршрутизацией.

111. Клиент читает в Kafka два последних сообщения. Как заново прочитать все с начала?▼

117. Знакомы ли вы с электронными подписями? Как работают?▼

Электронная подпись (ЭП) — криптографический механизм подтверждения авторства и целостности данных.

Принцип:
1. Документ хешируется (SHA-256)
2. Хеш шифруется приватным ключом отправителя → подпись

Виды в РФ:
• Простая ЭП (логин/пароль)
• Неквалифицированная ЭП
• Квалифицированная ЭП (юридическая сила как у собственноручной)

118. Что такое SFTP?▼

Отличия от FTP:
• Шифрование всего трафика (не только пароля)
• Аутентификация через SSH-ключи

Инструменты: WinSCP, FileZilla, OpenSSH, paramiko (Python).

126. Как вы использовали BPMN и UML в проекте?▼

BPMN: описывал процесс «Оформление заказа»:
• Участники: менеджер, система
• Поток: получение заявки → проверка наличия → уведомление клиента → внесение данных → обновление остатков → проверка адреса → завершение

UML Sequence: детализировал взаимодействие фронтенд → бэкенд → БД при добавлении блюда в меню.

ER-диаграмма: сущности Menu, Order, MenuSection, Photo; связи 1:M, M:N через промежуточные таблицы.
